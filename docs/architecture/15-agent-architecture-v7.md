# 文渊 · Agent 分析架构 v7（逐章提取 + 实体验收闸）

> **本文档取代 `14-agent-architecture-v6.md`（分片提取），为唯一权威。**
> 发现矛盾请回到本文档修正。

## 第一部分 · 为什么推翻 v6 的分片：三个问题共享一个根源

v6 提取层把 5-8 章拼成一片做单轮调用，换取调用次数从 57 降到 10 片。但分片让**"事实↔章节"归属不确定**，衍生出三个下游"猜章节"机制，在真实数据上全部失效：

| 问题 | 表象 | 分片时代打的补丁 | 儒林外史实测 |
|---|---|---|---|
| 章节事迹全空 | `chapterNo` 全挂片首章 | 模型输出 `chapterNo` + evidence 反查 | RELATION 132/134 ✅，**BIOGRAPHY 仅 24/91** ❌ |
| 传记定位失败 | BIOGRAPHY 是概述/改写句 | 强制 evidence 为本段原文 | 反查命中率 54-68%，**41% 完全无法定位** ❌ |
| 实体膨胀 | 模型过度列举 | 实体验收闸（保留） | 522 → ~200 |

**结论：提取任务的最优上下文是"单章"**（v6 §1 自己写了"提取是最优粒度小的局部任务"，分片只是省调用的工程手段）。v7 改为逐章提取，`chapterNo` 天然正确、`evidence` 天然在本章，**删掉全部"猜章节"机制**。

## 第二部分 · 一句话架构

> **逐章提取（单章上下文，天然带章节归属）→ 实体验收闸（确定性，实体从事实两端反推）→ 身份 Pass（紧凑名单全局折叠）→ 确定性归并 + dropped 清理 → 聚合 → 例外优先审核。**
> 没有 agent 循环、没有跨章记忆、没有"猜章节"。模型输出即证据，系统只验收。

## 第三部分 · 分层与管线

### 3.1 分层总览

```
┌──────────────────────────────────────────────────────────────┐
│ 验收层（工具化判据，代码而非 prompt）                          │
│  实体验收闸（锚定+从属指称+泛称过滤）· 关系码契约闭集校验        │
│  · dropped 清理（软删无持续身份称呼）· 分布式冲突扫描           │
│  · merge 人审门禁 · goldset 评测门禁 · 定向跨模型复核           │
├──────────────────────────────────────────────────────────────┤
│ 提取层（局部，模型自由发挥，prompt 极简）                      │
│  逐章提取（单轮）：实体 + 关系 + 传记事实，天然带章节归属       │
│  身份 Pass（全局，紧凑名单）：表面形式 → 规范实体（canonical） │
├──────────────────────────────────────────────────────────────┤
│ 上下文层（渐进式披露）                                        │
│  逐章提取注入"本章正文 + 全书摘要 + 相关 skill"                │
│  身份 Pass 注入"全书去重表面形式名单 + 提及频次"               │
├──────────────────────────────────────────────────────────────┤
│ 数据层（权威链）                                              │
│  facts ─► relationships（物化聚合）─► Neo4j（惰性同步）        │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 管线时序（v7，硬约束）

```
claim → 快照(selectSkillsForJob) → 装载(resolveSkillsForJob)
  → Pass1 逐章提取 + 落库（临时实体 + facts + mentions，片内共指，chapterNo=本章）
  → Pass1.5 身份 Pass（紧凑名单全局规范化 → 身份映射）
  → Pass1.75 确定性归并（临时实体 → canonical，facts/mentions 重指向）+ dropped 清理
  → Pass3 聚合（别名注册 + 幂等重建 relationships + Neo4j）
  → Pass4 自动接受（五条件）
  → Pass5 markOrphan + skillGenerator → 终态
```

**关键差异：提取粒度 = 单章，不再有"分片首章"归属问题。** 实体验收闸位于提取与落库之间（零 LLM，承重墙）。

### 3.3 各 Pass 职责

| Pass | 职责 | 是否 LLM | 调用数（儒林外史 56 章） |
|---|---|---|---|
| Pass1 逐章提取 | 单章提取实体/关系/传记；片内共指；chapterNo=本章 | 是 | 56 次（并发 ≤3，单章上下文小） |
| Pass1.5 身份 Pass | 全书去重表面形式名单 → canonical 实体 | 是 | 3-4 次（按类型，~4 分钟） |
| Pass1.75 归并+dropped 清理 | 临时实体按身份映射合并，facts/mentions 重指向；无持续身份称呼软删 | 否 | 0（确定性） |
| Pass3 聚合 | 别名注册 + 重建 relationships + Neo4j | 否 | 0 |
| Pass4 自动接受 | 五条件自动接受 + 冲突扫描 | 否 | 0 |
| Pass5 收尾 | markOrphan + SkillGenerator 候选 | 否（生成器未接线） | 0 |

**全书墙钟目标**：~15-25 分钟（v6 分片实测 ~8 分钟提取；逐章上下文小、可高并发，与分片持平或略快）。

## 第四部分 · Pass1 逐章提取（局部）

复用 v6 的 `extractSlice`（单轮提取）+ 实体验收闸（新增，见第五部分）。与 v6 差异：

1. **每章一次调用**（`buildSlices` 片大小 1）：`chapterNo` 天然等于本章，模型无需输出、代码无需反查。
2. **prompt 片内共指契约保留**：同一对象在本章的多个称呼并入一个实体（canonical 取本章最常见称呼，其余进 aliases）；不做跨章合并。
3. **证据必在本章**：`evidence` 是本章原文引用，章节事迹面板按章消费天然正确。
4. **落库即临时实体**：通过实体验收闸的表面形式经 `ensureEntityByName` 建临时实体（`recordSource=DRAFT_AI`），facts/mentions 引用之。

**成本澄清**：逐章 56 次调用 ≠ 5 倍成本。分片 10 片×6 章和逐章 56 章**读的正文总量相同**（都要读全书），总 token 几乎相同；单章上下文更短、每章独立可高并发，wall-clock 反而可能更快。DeepSeek 前缀缓存对"重复读整书"的分片更有利，但逐章省掉了全部定位纠错成本。

## 第五部分 · 实体验收闸（v7 新增，承重墙）

**问题（v6 的洞）**：实体存在性交给模型自由列举，身份 Pass 只折叠不删除 → 327 个 0 提及垃圾实体永久占位（`季苇萧的新娘`/`差人`/`轿夫`/一水地点）。

**v7 修复**：`guardrails.ts` 新增实体验收闸——**实体从保留事实的两端反推**，不再独立遍历 `slice.entities` 建实体。一个名字要成为实体，必须作为某条**通过验收的事实**的参与者：

1. **证据锚定**：名字在本章正文可证（归一化子串匹配，复用现有 `anchored`）
2. **从属指称过滤**：排除 "X的妻/妾/夫/母/师/师兄/新娘…"（新增 `isDependentReference`，保守正则）
3. **泛称/虚指过滤**：排除 `deicticJunk` 名单 + 单字（复用 `isDeicticJunk`）

任一不过 → 丢弃该事实并留痕（`dropRecords`），实体不建立。`runGuardrails` 新增返回 `entities`（= 保留事实的参与者名单）。

**效果**：0 提及垃圾在源头被挡；身份 Pass 只折叠"真实参与事实的实体"。类型信息从提取 `entities[]` 的 canonical/aliases 映射取（保留模型类型判断），事实落库时复用。

## 第六部分 · 身份 Pass 与 dropped 清理

### 6.1 身份 Pass（复用 v6）

输入 = 提取产出去重表面形式（实体名 + 提及频次 + 类型），输出 = `{canonical → aliases}` 映射 + dropped。紧凑名单（~10-15K token），模型一眼看到变体两端（范进/范老爷/范学道同屏），折叠是确定性分类任务。按类型（人物/地点/组织）各一次调用。

### 6.2 dropped 清理（v7 修正，从"仅降级置信"改为"软删"）

v6 规定 dropped"不软删实体，仅降级置信"→ 一次性称呼永久占位。v7 改为：

- 身份 Pass 判定 dropped 的名字 → **软删实体 + 软删其 mentions + 软删以其为主体的 facts**（同事务）
- 保留 `agent_write_audits` 审计（软删可追溯）
- 被吸收实体（projection 归并）软删语义不变

## 第七部分 · 与 v6 的差异清单

### 删除

| v6 组件 | 处置 | 理由 |
|---|---|---|
| 分片提取（5-8 章/片） | **改为逐章** | 章节归属从"猜"变"天然"；消灭所有定位机制 |
| `chapterNo` 模型输出 + evidence 反查兜底 | **删除** | 逐章后不需要；反查实测 41% 失败 |
| `slice.entities` 独立建实体 | **删除** | 实体从事实两端反推，0 提及垃圾源头被挡 |
| dropped 仅降级置信 | **改为软删** | 一次性称呼不再永久占位 |

### 保留 / 复用

| 组件 | 保留理由 |
|---|---|
| `extractSlice` / `guardrails`（含实体验收闸）| v7 的 Pass1 + 验收层 |
| `identityPass`（紧凑名单折叠）/ `projection`（归并）| Pass1.5 / Pass1.75 |
| `aliasResolver` / `refreshRelationshipsForBook` / `conflictScan` / `autoAccept` / `markOrphan` | Pass3-5 |
| `primitive`（跨模型复核）| 定向复核保留 |
| `registry`（派生视图）/ `getBookStatus`（进度推导）| 消费方不变 |

## 第八部分 · Prompt 设计（减法原则）

与 v6 §7 一致：systemPrompt ≤300-500 token，无分步流程/CRITICAL/负面指令/few-shot。两处变化：

1. **逐章提取**：删除 `chapterNo` 输出要求（模型读的就是本章，天然定位）；evidence 判据强调"本章原文引用"。
2. **身份 Pass**：不变（canonicalization 契约）。

## 第九部分 · 数据模型与计数口径

核心表不变：`facts`（唯一写入口）/ `entities` / `aliases` / `mentions` / `relationships`（派生）/ `analysis_jobs` / `agent_runs` / `agent_write_audits`。

**personaCount 口径（v7 修正）**：书库列表/详情人物数 = **PERSON 类型 ∧ 实体未软删 ∧ profile 未软删 ∧ 本书内 ≥1 mention**。不再把 LOCATION/ORG/CONCEPT 和 0 提及垃圾混入"人物"列。实现：`countEffectivePersonas`（mention→entity→profile 独立聚合，避开 `_count` 嵌套）。

## 第十部分 · 进度阶段

```
Pass1 extraction（10 → 45，按已完成章数推进）
Pass1.5 identity（50 → 65，按已完成类型调用数推进）
Pass3 aggregate（80）→ Pass4 auto_accept（90）→ Pass5 skill_generation（95）
```

## 第十一部分 · 评测与质量门禁

沿用 v5 §8 / v6 §10：goldset 跨段取样 + 冷门书对照 + eval gate（entityF1≥0.74 / relationF1≥0.68）+ 棘轮法 + 定向跨模型复核。

新增待验证点：

- **章节事迹覆盖**：逐章后 BIOGRAPHY 应分布到全部 56 章（不再集中片首章）
- **实体折叠 F1**：身份 Pass canonical 合并准确率（对照人工标注 aliases）
- **孤儿比例**：markOrphan 降级实体数应显著低于 v5/v6
